BUILD GUARD
npm run build verifies that all eight required assets exist in dist and match
their public source files byte-for-byte. It checks the app ID, Play signing
fingerprint, fallback HTML, proxy rule, JSON MIME configuration, and privacy
headers. Missing files fail the build instead of silently allowing SPA fallback.

LIVE CHECK
Run after the Git-connected deployment completes:
  npm run verify:app-links:live

This makes GET requests only. The association and script/style assets must not
redirect. Fallback HTML may use only its exact same-origin trailing-slash
canonical redirect, matching Cloudflare's default folder-index handling.
- /.well-known/assetlinks.json: 200 application/json, approved app/certificate.
- /open/stores: dedicated app-launch fallback, not the marketing homepage.
- /open/orders/1: generic fallback, never an API/order-data request.
- /open/app-link.js, /open/app-link-target.js, /open/app-link.css: actual assets.
- Fallback privacy headers: no-referrer, noindex, no-store.

A 200 text/html response for assetlinks.json is a failure, not success.
If post-deployment verification fails, the Worker upload may already have
succeeded. Inspect the URLs and domain/Worker mapping before retrying. A failed
final check does not necessarily mean that nothing was deployed.
The existing global SPA setting is unchanged. These checks protect required
app-link endpoints, not every website 404/SEO routing rule.
